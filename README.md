# tlk control

tlk.io 채널 메시지와 패들렛 게시물의 전송 간격·횟수를 설정하고, 진행 상태와 기록을 확인하는 도구입니다. Node.js 22 이상을 사용합니다.

## 로컬 실행

```powershell
$env:ALLOWED_ORIGINS='http://127.0.0.1:4173'
npm start
```

다른 터미널에서 `npm run preview`를 실행하고 `http://127.0.0.1:4173`을 여세요. 화면의 서버 연결 설정에 `http://127.0.0.1:3000`을 입력합니다. 테스트는 `npm test`로 실행합니다.

봇 수의 5개 제한은 없습니다. 봇 수와 총 전송 수는 정확한 집계를 위해 JavaScript가 안전하게 표현하는 정수 범위(1~9007199254740991)에서 입력합니다. 실제 생성 가능한 봇 수는 서버 자원과 서비스 제한에 따라 달라집니다. 전송 간격은 0~3600초이며 `0.0000001` 같은 작은 소수도 일반 십진수로 표시합니다. 지수 표기를 붙여 넣어도 입력란을 벗어나면 십진수로 바뀝니다. 총 전송 수에 소수는 사용할 수 없습니다. 실제 전송 속도는 타이머 정밀도와 네트워크 응답 시간에 따라 달라집니다.

## 패들렛 게시물

서비스 선택에서 **패들렛 게시물**을 고른 뒤 보드 주소 또는 ID, Padlet API 키와 본문을 입력합니다. 제목(최대 200자)과 섹션 ID는 선택 사항입니다. 첫 게시물을 즉시 생성한 후 설정한 간격마다 같은 내용의 새 게시물을 만들고, 총 횟수에 도달하면 종료합니다. tlk.io와 패들렛은 하나의 실행기를 공유하므로 동시에 한 작업만 실행할 수 있습니다.

1. 유료 Padlet 계정 또는 유료 Team·School 소속 계정의 [개발자 설정](https://padlet.com/dashboard/settings/developers)에서 API 키를 발급합니다.
2. 본인이 소유하거나 관리자 권한이 있는 보드의 주소를 입력합니다. 맞춤 주소는 보드의 더 보기 → Developer 메뉴에서 보드 ID를 확인해 사용합니다.
3. 특정 섹션에 게시하려면 보드 조회 API에 `?include=sections`를 붙여 얻은 섹션 ID를 입력합니다. 생략하면 섹션을 지정하지 않습니다.
4. 본문(1~1,000자), 간격, 총 게시 수를 설정하고 시작합니다. 모니터의 **보드 열기**로 결과를 확인하고, **실행 중지**로 남은 게시를 취소할 수 있습니다. 이미 서버에 전달된 게시 요청은 취소되지 않을 수 있습니다.

공식 `POST https://api.padlet.dev/v1/boards/{board_id}/posts` API와 `X-API-KEY` 인증을 사용합니다. 텍스트 게시를 지원하며 첨부파일·댓글·기존 게시물 수정은 포함하지 않습니다. 전송 제한이나 권한 오류, 확인할 수 없는 응답은 자동 재시도 없이 중지합니다. API가 생성한 게시물 ID를 반환한 경우에만 완료 건수를 늘립니다. 보드의 검토 설정에 따라 생성된 게시물이 승인 대기 상태일 수 있습니다.

API 키는 시작 요청으로 선택한 실행기 서버에 전달되고 실행 중 메모리에서만 사용됩니다. 상태 응답·로그·브라우저 저장소에 넣지 않으며, 시작 성공 후 입력란을 비웁니다. 본인이 관리하거나 신뢰하는 HTTPS 실행기를 사용하세요. 기존 실행기 API는 인증 없이 공유되는 구조이므로 서버 URL을 아는 사람은 상태 조회와 중지가 가능합니다.

- [Padlet 인증과 이용 조건](https://docs.padlet.dev/reference/authentication)
- [게시물 생성 API](https://docs.padlet.dev/reference/add-post)
- [보드와 ID 안내](https://docs.padlet.dev/reference/board-object)

실제 게시는 유효한 API 키와 보드가 필요합니다. 자동 테스트는 외부로 게시하지 않고 API 요청 형식, 오류 처리, 중지, API 키 비노출을 검증합니다. 배포 시 정적 화면과 실행기 서버를 함께 업데이트하세요.
